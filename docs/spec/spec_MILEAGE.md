# Spec MILEAGE: пробег авто не больше 400 000 км, иначе решение review

Источник требований: `docs/intent/intent_MILEAGE.md` (+ `grill_MILEAGE.md`, `plan_MILEAGE.md`).
Что именно считается сделанным — здесь; как реализовывать — `plan_MILEAGE.md`.

## Входит / не входит

**Входит:**

- Проверка пробега в расчёте итогового решения: пробег свыше 400 000 км понижает
  итоговое решение `approve` → `review` (REQ-MILEAGE-01…03, 05).
- Порог 400 000 км как параметр правила (REQ-MILEAGE-02).
- Нулевой `approved_limit` при понижении до `review` (REQ-MILEAGE-05).
- Сохранение текущей валидации пробега 0…500 000 км без изменений (REQ-MILEAGE-06).

**Не входит** (источник: `intent_MILEAGE.md`, раздел «Не входит»; `grill_MILEAGE.md`, вопрос 5):

- Пересчёт `approved_limit` по возрасту авто (LOAN-12). Источник: `plan_MILEAGE.md`.
- Сверка пробега по VIN с внешним справочником (CASE-08). Источник: `plan_MILEAGE.md`.
- Фронтенд, хранение в БД, изменение валидации пробега. Источник: ответы в интервью
  (вопросы 2, 5); `plan_MILEAGE.md`.
- Отдельный флаг/причина «пробег» в ответе — открытый вопрос 3, не входит до его решения.

## Требования

- **REQ-MILEAGE-01.** Если решение по LTV — `approve` и пробег больше 400 000 км,
  итоговое решение — `review`. Источник: `intent_MILEAGE.md` (замысел; constraints,
  п. 1–2); формулировка задачи в интервью.
- **REQ-MILEAGE-02.** Порог правила — 400 000 км, сравнение строго «больше»; пробег
  ровно 400 000 км решение не понижает. Источник: `intent_MILEAGE.md` (constraints,
  п. 1: «не больше 400 000 км»); `plan_MILEAGE.md` (вопрос 1, решение плана — до
  ответа Арсения, см. Open questions № 1).
- **REQ-MILEAGE-03.** Правило — только понижение `approve` → `review`: решения `review`
  и `reject` при пробеге свыше порога не изменяются (не повышаются и не смягчаются);
  `reject` не выдаётся из-за пробега. Источник: `intent_MILEAGE.md` (constraints,
  п. 2, 7); `grill_MILEAGE.md` (вопрос 3).
- **REQ-MILEAGE-04.** Пробег не влияет на расчёт LTV: LTV вычисляется как раньше,
  правило применяется после решения по LTV и независимо от него. Источник:
  `intent_MILEAGE.md` (constraints, п. 4–5); `grill_MILEAGE.md` (вопрос 4).
- **REQ-MILEAGE-05.** При понижении решения до `review` одобренный лимит по заявке
  равен 0. Источник: `intent_MILEAGE.md` (constraints, п. 6); `grill_MILEAGE.md`
  (вопрос 4).
- **REQ-MILEAGE-06.** Валидация пробега не меняется: допустимый диапазон 0…500 000 км;
  пробег отсутствует (пустой/нет ключа `mileage`), отрицательный или свыше 500 000 км —
  ошибка валидации, до правила решение не доходит. Источник: `intent_MILEAGE.md`
  (constraints, п. 3); `grill_MILEAGE.md` (вопрос 2); код: `ApplicationValidator`
  (`backend/src/Domain/ApplicationValidator.php:43–46`), `rules.php` (`max_mileage_km` = 500 000).

## Критерии приёмки

Формат Given / When / Then. Базовый сценарий для границ: LTV низкий (например,
450 000 / 900 000 = 50 %), при котором без правила решение было бы `approve`
(источник сценария: `plan_MILEAGE.md`, раздел 3).

- **AC-MILEAGE-01** (REQ-MILEAGE-01, 02). Given заявка с LTV 50 % (по LTV — `approve`)
  и пробегом **399 999 км**; When рассчитывается решение; Then `decision = approve`,
  `approved_limit` как при `approve` (не 0).
- **AC-MILEAGE-02** (REQ-MILEAGE-02). Given заявка с LTV 50 % и пробегом ровно
  **400 000 км**; When рассчитывается решение; Then `decision = approve` (порог
  «не больше 400 000», понижение строго `>`).
- **AC-MILEAGE-03** (REQ-MILEAGE-01, 05). Given заявка с LTV 50 % и пробегом
  **400 001 км**; When рассчитывается решение; Then `decision = review`,
  `approved_limit = 0`.
- **AC-MILEAGE-04** (REQ-MILEAGE-03). Given заявка с LTV, дающим `review` по LTV
  (например, в диапазоне ≤ 85 %), и пробегом **400 001 км**; When рассчитывается
  решение; Then `decision = review` (не `reject`, не `approve`), `approved_limit = 0`.
- **AC-MILEAGE-05** (REQ-MILEAGE-03). Given заявка с LTV, дающим `reject` по LTV
  (выше 85 %), и пробегом **400 001 км**; When рассчитывается решение; Then
  `decision = reject` (пробег не смягчает и не меняет `reject`).
- **AC-MILEAGE-06** (REQ-MILEAGE-04). Given заявка с пробегом **400 001 км**; When
  рассчитывается LTV; Then LTV равен `запрошенная сумма / оценочная стоимость` — тем же
  значением, что и при любом другом пробеге (пробег в расчёт LTV не входит).
- **AC-MILEAGE-07** (REQ-MILEAGE-06). Given заявка, в которой ключ `mileage` отсутствует
  или пробег пуст; When заявка валидируется; Then ошибка валидации («Пробег от 0 до
  500 000 км»), до расчёта LTV и правила дело не доходит.
- **AC-MILEAGE-08** (REQ-MILEAGE-06). Given заявка с пробегом **500 001 км** (или
  отрицательным); When заявка валидируется; Then ошибка валидации, до правила дело не
  доходит (правило реально действует в диапазоне 400 001…500 000 км).

Граница 500 000 км не является границей правила MILEAGE (порог правила — 400 000 км,
источник: `intent_MILEAGE.md`); AC-MILEAGE-08 фиксирует лишь неизменность существующей
валидации.

## Источники чисел

- **400 000 км** — порог понижения решения. Источник: формулировка задачи в интервью
  («не больше 400 000 км, иначе решение review»), `intent_MILEAGE.md`, constraints п. 1.
  Чтение границы «ровно 400 000 → `approve`» — `plan_MILEAGE.md` (вопрос 1), до ответа
  Арсения.
- **500 000 км** (`max_mileage_km`) — верхняя граница валидации пробега, существует
  до задачи MILEAGE и не меняется. Источник: `intent_MILEAGE.md`, constraints п. 3;
  `grill_MILEAGE.md`, вопрос 2; код: `backend/config/rules.php`, `ApplicationValidator`.
- **50 % / 450 000 из 900 000** — тестовый LTV для AC, при котором без правила было бы
  `approve`. Источник: `plan_MILEAGE.md`, раздел 3.
- **85 %** — граница LTV `approve`/`review`/`reject`, существует до задачи MILEAGE.
  Источник: `grill_MILEAGE.md`, вопрос 4; `plan_MILEAGE.md`.
